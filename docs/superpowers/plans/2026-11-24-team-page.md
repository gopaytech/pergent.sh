# Team page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One tabbed team page at `/teams/:id` (Repositories, Members, Models, Limits, Usage), a team usage route, a server search for adding repositories, and an optional owner team when an admin switches a repository on.

**Architecture:** 3 new read routes (`GET /api/teams/{id}`, `.../usage`, `.../repository-choices`) and one new optional field on `POST /api/repositories`. The tabs save through today's `PUT /api/teams/{id}`, built in the browser from the page's last read plus one change. Team usage reads `splitUsageSQL`, which gets an `owner_team_id` column. Switch-on with an owner runs the insert or resume and the team change in one transaction.

**Tech Stack:** Go 1.24, pgx v5, Postgres 13+, React + TanStack Query + Vite, vitest.

**Spec:** `docs/superpowers/specs/2026-11-24-team-page-design.md` (its Anti-goals are the failure bar).

## Global Constraints

- **Local tests are focused only.** Go: `go test -count=1 ./internal/<pkg>/ -run '^(A|B)$'` with exact names and a closing `$`. Web: `npx vitest run <changed test files>`. Plus `go vet ./...`, `npm run typecheck`, `npm run lint`. Never `go test ./...`, a whole package, `make test` or a bare `npx vitest run`, also not after a rebase or a merge. CI's `test` and `web` checks are the full run.
- DB tests need `PERGENT_SH_TEST_DATABASE_URL='postgres://postgres:postgres@localhost:55432/pergent_test?sslmode=disable'` **in the same command** as `go test` (written `$DB` below). Check `nc -z localhost 55432` first. If it is down, say so and leave DB tests to CI. Never start a container (no `docker`, no `orbctl`).
- Fast tests: test at the lowest level that proves it (a pure function gets a plain unit test). One `newStore`/`newEnv`/`newTeamsEnv` per test, with the variants as `t.Run` table subtests. `t.Parallel()` unless the test sets a package variable or env. No `time.Sleep`. Use the fake clock (`e.clock.advance`) and fake timers. Budget: Go unit <100 ms, DB <2 s, web <500 ms.
- Every route change goes in `openapi.yaml` (`x-pergent-access: admin` for admin routes, `session` otherwise) and `docs/reference/http-routes.md`. Every new type in `view.go` goes in `openAPISchemas` (`internal/dashboard/openapi_test.go`), and every new web call goes in `web/src/api.ts`. Offline gate: `go test -count=1 ./internal/dashboard/ -run '^(TestOpenAPIRoutesMatchCode|TestOpenAPISchemasMatchGoTypes|TestOpenAPIEveryViewTypeHasASchema|TestOpenAPIDocumentIsValid|TestAdminRoutesAreRegisteredOnlyThroughTheHelper)$'`.
- Docs change in the same task as the behaviour. Upgrade notes go under a new `## Unreleased` heading at the top of `docs/upgrading.md`. Docs prose: no `→` in UI paths ("the admin **Teams** page").
- `PUT /api/teams/{id}` does not change. No new member or repository write routes. Who may change what does not change.
- No release, no version bump, no chart change.
- Easy English in docs and UI copy. No internal names in this public repo. Run the private-name scan before each commit. `web/` has no prettier, so format by hand. eslint is the gate.
- A worktree with no `web/node_modules`: `cp -Rc` another checkout's `web/node_modules` in. Never use a symlink.
- Admin-only routes register through `Dashboard.adminRoute` (404 for a non-admin). Team session routes use `teamFor`.

## Review Focus

1. **A save from one tab while the other tab's data is unusual** (an invited member, a member added by another admin since the read): the PUT must carry the members and entries exactly as read. Pinned by `teamUpdate` unit tests (Task 5) and the "untouched tab" web test (Task 6).
2. **An entry that is no longer switched on, or whose instance is being removed:** `GET` marks it `removed`, and every save leaves it out instead of getting a 400 `msgRepoNotOn`. Pinned in `TestTeamPage` (Task 1) and `teamUpdate` (Task 5).
3. **The same repository in another case** (`Acme/Widgets` on the team, `acme/widgets` switched on): it is not offered again in the search. Pinned in `TestRepositoryChoices` (Task 2).
4. **A multi review on a team repository:** it counts once, each Job on its model. It must not be counted from both `run_usage` and `run_usage_by_model`. Pinned in `TestTeamUsage` (Task 3).
5. **`ownerTeam` for a repository whose instance entry has another owner team:** this is not a conflict, because the repository's own entry wins. Only a repository-level owner makes it 409. Pinned in `TestSwitchOnOwned` (Task 4).
